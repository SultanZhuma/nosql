## 1. Назначение проекта

Учебный прототип графовой модели системы бронирования на **Neo4j**. В графе представлены пользователи, ресурсы (гостиничные номера и другие объекты бронирования) и локации. Модель поддерживает поиск бронирований, фильтрацию ресурсов, переход к локации и поиск альтернатив в соседних местах.

Все данные синтетические; реальные персональные данные не используются.

## 2. Используемые технологии

| Компонент | Назначение |
|---|---|
| Neo4j Community (`neo4j:5`) | Графовая база данных |
| Cypher | Создание и запросы к property graph |
| Neo4j Browser | Выполнение запросов и визуализация графа |
| Docker Compose | Запуск локальной учебной среды |

## 3. Требования к окружению

1. Docker Desktop установлен и запущен (`docker --version`).
2. Свободны локальные порты `7474` и `7687`.
3. При первом запуске нужен интернет для загрузки Docker-образа.
4. Также можно использовать Neo4j Desktop или AuraDB, выполнив Cypher-файлы вручную.

## 5. Быстрый запуск (5 действий)

Команды выполняются в терминале из корневой папки проекта.

```bash
# 1. Запустить контейнер, дождаться готовности, создать ограничения и данные,
#    затем проверить количество узлов и отношений:

# 2. Открыть Neo4j Browser:
# http://localhost:7474

# 3. Войти пользователем neo4j с учебным паролем из docker-compose.yml

# 4. Выполнить Q01–Q08 по одному из файла:
# Код проекта/cypher/04_queries_Q01-Q08.cypher

# 5. Продемонстрировать изменение и безопасное удаление из файла:
# Код проекта/cypher/05_update_and_safe_delete.cypher
```

Остановка контейнера:

```bash
docker compose down
```

> Важно: пароль в `docker-compose.yml` предназначен только для локального учебного стенда. Не используйте его для реальных или открытых в интернет систем. Если Neo4j попросит сменить пароль при первом входе, обновите `DB_PASSWORD` в `scripts/run_all.sh` в соответствии с установленным паролем.

## 6. Подробная инструкция

### 6.1. Запуск Neo4j

Автоматизированный скрипт `scripts/run_all.sh` запускает Docker Compose, ожидает готовности сервера, применяет ограничения и загружает учебные данные. Проверка соединения в Browser:

```cypher
RETURN 'Neo4j works' AS status;
```

Ожидаемый результат — одна строка со значением `Neo4j works`.

### 6.2. Модель данных

| Метка узла | Назначение | Основные свойства |
|---|---|---|
| `User` | Пользователь | `userId`, `name`, `email` |
| `Resource` | Ресурс бронирования | `resourceId`, `name`, `resourceType`, `pricePerNight`, `capacity`, `available` |
| `Location` | Место / локация | `locationId`, `name`, `city`, `kind` |

| Отношение | Направление | Назначение |
|---|---|---|
| `BOOKED` | `User → Resource` | Бронирование; свойства `bookingId`, `checkIn`, `checkOut`, `status` |
| `LOCATED_IN` | `Resource → Location` | Размещение ресурса в локации |
| `NEAR` | `Location → Location` | Соседство; свойство `distanceKm` |

Графовая схема находится в `docs/architecture.png`.

### 6.3. Загрузка данных и ожидаемые количества

`02_seed_data.cypher` создаёт 6 пользователей, 8 ресурсов и 5 локаций — всего **19 узлов**. В исходном графе содержатся 8 отношений `BOOKED`, 8 `LOCATED_IN` и 8 `NEAR`, всего **24 отношения**.

Для уникальных идентификаторов используются ограничения. `MERGE` позволяет повторно выполнять загрузку без дублирования соответствующих узлов и отношений.

### 6.4. Демонстрационные запросы

| № | Операция | Назначение |
|---|---|---|
| Q01 | `MATCH` | Список пользователей |
| Q02 | Фильтрация | Доступные ресурсы в бюджетном диапазоне |
| Q03 | `ORDER BY`, `LIMIT` | Три самых дешёвых доступных ресурса |
| Q04 | `BOOKED` | Бронирования выбранного пользователя |
| Q05 | Двухшаговый обход | Пользователь → ресурс → локация |
| Q06 | `NEAR*1..2` | Обход по соседним локациям с ограниченной глубиной |
| Q07 | `count()` | Число бронирований пользователя |
| Q08 | Комбинированный обход | Альтернативные ресурсы в соседних локациях |

Выполняйте запросы Q01–Q08 по одному, чтобы было удобно сохранять результаты для отчёта.

### 6.5. Изменение и безопасное удаление

Файл `05_update_and_safe_delete.cypher` изменяет свойство `available` ресурса `R008`, показывает тестовую связь `B007` перед удалением, удаляет только эту связь и повторно проверяет её отсутствие.

**Перед командой `DELETE` обязательно запустите запрос с `RETURN` и проверьте, что выбран путь `U006 — B007 — R008`.** Запускайте этот сценарий только в учебной базе. После удаления число отношений `BOOKED` должно уменьшиться с 8 до 7, а общее количество отношений — с 24 до 23.

## 8. Обоснование выбора Neo4j

Главный паттерн доступа проходит через цепочки: пользователь → бронирование → ресурс → локация → соседняя локация. В Neo4j отношения являются частью модели, поэтому многошаговый поиск выражается непосредственно в Cypher.

Документная модель может быть проще для независимых карточек ресурсов, но хранение списков идентификаторов для многошаговых обходов требует дополнительной логики и может усложнить согласованное обновление связей. Более подробное архитектурное решение находится в `docs/ADR.md`.

## 9. Ограничения и масштабирование

- Ограничивать глубину обходов, например `NEAR*1..2`.
- Использовать уникальные идентификаторы и `MERGE` для предотвращения дублей.
- Проверять сложные запросы с помощью `EXPLAIN` и `PROFILE`.
- При увеличении объёма данных оценивать индексы, частоту запросов и распределение связей.
- Использовать только синтетические данные.
